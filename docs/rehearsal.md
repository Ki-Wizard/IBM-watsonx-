# 가막만 시연 검증 기록

## 협업 시연

1. `GAMAK_MODE=watsonx`로 앱을 시작하고 사이드바에서 **새 데모 시작**을 누릅니다. 시점 B 예시를 불러와 **판단 요청**을 누릅니다. **IBM 협업 · 원문 검색 확인**과 근거 조사·당직 지원·승인함의 상태를 확인합니다. 인계 요약을 열어 호출 순서와 실행 이력 ID를 확인하고, **기존 안내와 새 초안**에서 경보별 원문 링크를 엽니다.
2. 같은 질문을 다시 제출합니다. **IBM 협업 결과 재사용** 상태에서 승인함이 `0 → 1 → 1`이고 실행 이력 ID와 초안 ID가 같은지 확인합니다.
3. **해제 범위 불명 사례**를 불러옵니다. 8월 29일 가상 승인본과 8월 30일 10:00이 채워집니다. **판단 요청**을 눌러 `확인 필요`, 해제 범위 질문, 초안 건수 유지를 확인합니다.
4. **가막만 특보 해제 · 9월 26일**을 불러오고 **판단 요청**을 누릅니다. [시연 요청](../examples/gamak-release.request.json)의 질문은 “가막만도 특보 해제 대상인가요?”입니다. 적조정보가 연결된 경우 인계 요약에서 목록과 상세 조회를 확인하고, 가막만 해제 원문과 정부 `주의` 하향 발령 근거를 각각 엽니다. 보관 자료 경로에서는 9월 25일 해양수산부 발표로 같은 지역 범위를 확인합니다.

같은 IBM 대화 이력에서 위임과 원문 검색의 기록을 각각 확인합니다. 화면의 인계 순서는 배포한 두 에이전트의 역할을 요약합니다. 지역 특보와 정부 위기경보의 인용은 각각 공식 발췌 ID와 대조합니다. 원문, 기준시각, 판정이 검증된 경우에만 IBM 경로로 기록합니다. 이 흐름은 공개 문서의 저장된 발췌를 검색하는 역사 시연입니다.

### 교육 계정 협업 검증

2026년 11월 20일(KST)에 배포하고 실행했습니다.

| 요청 | 검증된 판정과 승인함 |
| --- | --- |
| 대표 갱신 후 반복 | `갱신 필요`, `0 → 1 → 1`, 동일 초안 ID |
| 8월 26일 승인 직후 | `유지`, `0 → 0` |
| 8월 해제 범위 불명 | `확인 필요`, `1 → 1`, 해제 대상 확인 질문 |
| 9월 25일의 같은 해제 질문 | `갱신 필요`, `1 → 2`, `mof-63302`의 두 발췌 |
| 수온 누락 | `갱신 필요`, `0 → 1`, 수온 `확인 필요` |

실호출 과정에서 간헐적으로 판정·인용 또는 검색 이력 검증에 실패했습니다. 8월 해제 질문은 이전 브라우저 리허설에서 로컬로 재현했고, 새 빈 승인함으로 진행한 발표 리허설에서는 8월과 9월 해제 질문 모두 IBM 협업이 확인됐습니다. 로컬에서도 “가막만 안내를 종료해도 되나요?”는 8월 기준으로 `확인 필요`와 `0 → 0`을 표시합니다. 수온 누락 사례는 로컬 전환 시에도 수온을 `확인 필요`로 유지합니다. 검증되지 않은 IBM 응답은 승인함에 쓰지 않습니다.

## IBM 교육 계정의 단일 에이전트 시연 기록

2026년 11월 20일(KST) 실행했습니다.

| 확인 항목 | 결과 |
| --- | --- |
| 교육 계정 IAM 인증·에이전트 목록 | HTTP 200 |
| `kiw_gamak_smoke_agent` 배포 | 성공 |
| 테스트 질문과 `kiw_gamak_smoke_lookup` | 채팅 HTTP 200, 대화 이력에서 도구 응답과 검증 코드 일치 확인 |
| `kiw_gamak_red_tide` 프로젝트 에이전트 배포 | 팀 프롬프트의 핵심 원칙을 포함한 버전 배포 성공 |
| 공식 근거 도구 `kiw_gamak_official_evidence` | 대화 이력에서 실제 도구 결과 1건을 확인하고 판정·근거·실행 코드를 검증 |
| Streamlit과 SQLite 연결 | 화면에서 IBM 실호출 표시와 승인함 `0 → 1 → 1` 확인 |

두 경보와 근거 본문은 IBM 대화 이력의 공식 근거 도구 결과에서 읽습니다. 모델은 판정과 근거 ID를 반환하고, 백엔드는 도구 결과 및 로컬 공식 자료와 대조한 뒤 공통 JSON 형식과 승인함 상태를 반환합니다. 응답 검증에 실패할 경우 동일 승인함을 사용하는 로컬 재현 경로가 화면에 표시됩니다.

팀의 질문과 기대 결과는 `examples/test-cases/`에 있습니다. 갱신, 반복 요청, 해역 불명은 같은 DB에서 실행했습니다. 다른 사례는 각각 빈 DB로 시작했습니다.

| 사례 | 실행 | 판정 | 승인함 | 확인 내용 |
| --- | --- | --- | --- | --- |
| 갱신 | IBM | 갱신 필요 | 0 → 1 | 가막만 적조주의보 14:00 및 정부 경계 16:00을 별도로 표시 |
| 유지 | IBM | 유지 | 0 → 0 | 8월 26일 17:00 기준으로 8월 29일 발표 제외 |
| 반복 요청 | IBM | 갱신 필요 | 1 → 1 | 첫 갱신 요청과 동일한 초안 ID 재사용 |
| 해역 불명 | IBM | 확인 필요 | 1 → 1 | 8월 29일 발표에 근거를 연결하고 가막만의 해제 범위를 확인 질문으로 남김 |
| 수온 누락 | IBM | 갱신 필요 | 0 → 1 | 수온은 확인 필요로 남기고 두 경보 변경을 초안에 반영 |
| 공식 자료 조회 실패 | 로컬 | 확인 필요 | 0 → 0 | 자료 파일이 없는 상황을 재현하고 확인 이력 저장 |

## 발표 큐시트

| 순서 | 화면에서 할 일 | 보여줄 결과 |
| --- | --- | --- |
| 1 | 사이드바에서 **새 데모 시작**을 누릅니다. **과거 승인본 미리보기**를 열어 8월 26일 가상 승인본을 보여줍니다. | 빈 승인함, 승인 시각 16:15 KST, 예비특보·주의 |
| 2 | **두 기준시각 비교**를 누릅니다. | 같은 질문과 승인본으로 8월 26일 16:30은 `유지`, 8월 29일 16:30은 `갱신 필요`. 29일 경계 발령 자료가 추가되며 승인 대기는 0건입니다. |
| 3 | **예시 질문**에서 시점 A를 골라 **예시 불러오기**를 누르고 **판단 요청**을 누릅니다. | `유지`, 승인함 `0 → 0` |
| 4 | 시점 B를 불러와 **판단 요청**을 누릅니다. **기존 안내와 새 초안**에서 두 경보의 원문 링크를 보여줍니다. | `갱신 필요`, 승인함 `0 → 1` |
| 5 | **동일 요청 반복** 예시를 선택해 안내를 보여주고, 입력을 그대로 **판단 요청**합니다. | 동일 초안 재사용, 승인함 `1 → 1` |
| 6 | **발표 타임라인**을 엽니다. | 29일 발표 자료는 16:00부터 조회되고, 가막만 특보는 14:00에, 정부 경보는 16:00에 발령됐습니다. 판정에 반영된 발표와 기준시각 이후 자료를 구분합니다. |
| 7 | **해제 범위 불명 사례**를 불러와 판단합니다. 확인 담당자와 메모를 입력하고 **메모 저장 및 재판단**을 누릅니다. | `확인 필요`와 적조속보 확인 질문. **전체 검토 이력**에서 메모 확인. |
| 8 | **당시 수온 누락 사례**를 불러와 판단합니다. 새 초안 등록을 보여주려면 이 사례를 빈 데모에서 실행합니다. | 적조주의보·경계 변경과 실측 수온 `확인 필요`. 같은 DB에 동일 근거의 초안이 있으면 재사용합니다. |
| 9 | **승인함 · 검토 이력**에서 초안을 선택하고 처리 담당자와 메모를 입력한 뒤 **승인** 또는 **반려**를 누릅니다. | 상태, 처리 시각, 담당자와 메모, 초안의 재사용 이력 |
| 10 | **새 데모 시작**으로 빈 승인함을 열고 **열린 승인함** 목록에서 직전 데모나 **리허설 DB**를 선택합니다. | 기존 초안과 승인·반려 및 검토 기록을 다시 열 수 있습니다. |

예시 질문을 불러오면 네 입력만 채워집니다. 기준시각 비교는 보관 자료로 확인하고, 판단 요청과 메모 저장 및 재판단은 선택된 SQLite에 기록합니다.

### 적조정보 API와 후속 확장

적조속보 등록일이 9월 25일이고 게시시각은 확인되지 않아 시연 기준시각을 9월 26일 10:30 KST로 잡았습니다. 같은 9월 25일 속보라도 그날의 분 단위 기준시각까지 확인할 수 있었는지 불명확하면 **확인 필요**를 표시합니다.

2026년 11월 21일 교육 인스턴스에서 **“가막만도 특보 해제 대상인가요?”**를 실행했습니다. 인증된 목록과 상세가 모두 결과 코드 `00`을 반환했고, 두 에이전트의 실제 인계와 목록 → 상세 도구 실행을 확인했습니다. 지역 특보 `해제`는 적조속보 `20250925-001`, 정부 위기경보 `주의`는 해양수산부 보도자료 `63302`를 인용했습니다. 새 데모의 승인함은 `0 → 1`이었습니다.

이번 외부 근거는 적조정보에 집중합니다. 후속 단계에서는 실시간 수온을 관측 근거로 연계하고 시계열 데이터 기반 예측 모델을 도입해 위험 예측으로 확장할 수 있습니다.
